# v1.0.15 优化记录与测评

日期：2026-11-07　基线：v1.0.14（本目录 `cordis.patch.yml` 内 `inlineChars: 1600`）
语料：本机 162 个真实会话解出的 **12,861 条工具结果 / 7.46M 字符**（`tools/extract-corpus.mjs`，2026-11-07）

## 1. 结论

| 指标 | v1.0.14（1600） | v1.0.15（1200） | 变化 |
|---|---|---|---|
| 工具结果字符总量 | 7.46M → 6.07M | 7.46M → **5.98M** | 省量 18.7% → **19.8%** |
| 被中段裁剪的结果 | 346 条 | 1,069 条 | 覆盖更多大结果 |
| 被裁剪结果的中位成品长度 | 606 字符 | **1,092 字符** | 同样预算下多留 **80.2%** 内容 |
| 预算利用率（p50 / p90） | 0.38 / 0.76 | **0.91 / 0.96** | 预算不再被浪费 |
| 超过内联预算的文本块 | 0 | **0** | 硬上界仍成立 |
| read 裁剪结果带文件行号区间 | 0 / 134 | **134 / 134** | 可精确续读 |
| 单测 + 真实语料不变量 | 96 项（语料路径失效时 21 项跳过） | **102 项全过** | 语料组 12/12 |
| 单条开销（中位 / p95） | 0.004 / 0.025 ms | 0.005 / **0.108 ms** | 裁剪条数变多，尾部变重；相对一次工具调用仍可忽略 |
| 被裁剪结果**自身**的压缩率 | 52.9% | **55.9%**（2.64M → 1.16M） | 同样的说明行开销，装下更多原文 |

一句话：**省得更多（+1.1pp），同时每条被裁剪结果多留 80% 的内容**；这不是"多花 token 换信息"，
而是把原先浪费掉的预算（p50 只用了 38%）用满了。

## 2. 改了什么（全部有真实语料或单测证据）

| # | 问题（证据） | 改动 | 位置 |
|---|---|---|---|
| 1 | 单行/minified 结果退化成"只有一个被截断的头"：2,951 字符的 MCP JSON 只剩 589 字符，尾部为空 | 首行窗口封顶 `maxUnitChars × 3`，长首行照常切分 | `lib/sections.js` `sectionsOf` |
| 2 | 三份预算各自按比例切，切完只花掉 38%（p50） | 头部缺口按整单元回填，最后一块可截断收尾；回填行同步从"可疑行"候选剔除 | `lib/retain.js` 3.5 节 |
| 3 | read 的续读 footer 会被中段填充挤掉（真实语料 2 条失败） | `<path>/<type>/<content>/</content>/(End of file…)/(Showing lines…)` 提为优先级 2，并从尾部预算**预扣**信封额度 | `lib/sections.js` `markReadStructure`、`pickSections` |
| 4 | 末单元从**后面**截断，`}]`、退出状态、`</content>` 一起消失 | 末单元改为保留后缀（`clipTail`） | `lib/sections.js` |
| 5 | 说明行只说"49 lines"，模型无法定位该补哪一段 | 说明行加 `file lines 12-35` / `lines 4-52`（read 映射到**文件行号**） | `lib/retain.js` `omittedRangeText` |
| 6 | 可疑行判重只比文本，尾部被裁剪后同一行会重复且倒序（`60 … 44 … 46`） | 改为按**绝对单元下标**判重 | `lib/retain.js` `selectImportantLines` |
| 7 | 词中被切：`…scripts.` → `…ripts.`，造出不存在的标识符 | `clipLine` 在词边界收刀（找不到空格才硬切） | `lib/sections.js` |
| 8 | 只有行号的空行（`44:`）占满尾部预算 | 空单元不参与尾部挑选（末行除外） | `lib/sections.js` `isEmptyUnit` |
| 9 | 同机另一层 `dsh-exec-optimizer` 先裁过一次，本插件再裁会把 read 的 `<path>` 挤没 | read 遇 `omitted by dsh-exec-optimizer` / `exec-optimizer-spill` 只做无损规范化 | `lib/policy.js` |
| 10 | 认不出别家的 spill 路径，说明行退回"重跑命令" | `findRecoveryPath` 增加 `Full text: /path` | `lib/retain.js` |
| 11 | 12,861 条里有 1 条成品超预算 15 字符（说明行自带的摘要把成品顶出去） | 收尾闸门：先撤摘要，再整块撤补充尾块；主尾块与末单元**永不撤** | `lib/retain.js` 收尾段 |
| 12 | README 声称"每一步都可逆"，但 `blank-runs`（≥4 换行折成 3）不可逆 | 语料测试改成"空行数量除外逐字节一致"，并在文档里写明唯一单向步骤 | `test/corpus.test.js`、README |

## 3. 测评方法与数据

### 3.1 语料与口径

- 语料：`node tools/extract-corpus.mjs` 从 `~/.dsh/sessions` 解压，162 个会话、185.4 MB 原始日志，
  得 12,861 条真实工具结果（7.46M 字符）。其中 2,255 条**本身已被旧版本裁剪过**（回放时不会二次变小），
  所以整体省量会被稀释；只看"未裁剪过的结果"时旧版省 25.2%、新版省 27.6%。
- 计费口径：`estimateContent`（与 DSH 官方估计器同构，UTF-16 长度 / 4）。
- 单会话省量分布（129 个会话）：p50 **3.1%**、p75 6.4%、p90 60.1%、最高 76.9%；
  28 个会话省量 >10%。分布是双峰的——MCP/长日志用得多的会话省得多，
  只跑短命令的会话本来就没有可压的字符。
- 对照：把 v1.0.14 的 `lib/` 原样备份后，用**同一份语料、同一套参数**回放。

## 5. 部署与回滚

- 生效需要**重启 DSH**：插件源码是 `link:` 安装，但宿主已把旧模块载入内存。
- 回滚：`inlineChars` 改回 `1600`（`cordis.patch.yml` 或 profile 覆盖层），其余改动是纯行为修复，无需回滚。
- 复测：`node tools/bench2.mjs .corpus/raw --budget 1200`；语料组测：
  `DSH_OPTIMIZER_CORPUS=$PWD/.corpus/raw node --test test/*.test.js`。

## 6. 仍然存在的风险

1. 本机 profile 同时装了三个优化器（`dsh-exec-optimizer`、`dsh-optimizer`、本插件），
   职责重叠。本版只做到了"read 不二次裁剪"，没有做统一的优先级仲裁。
2. 语料来自单机 162 个会话，工具分布偏向 bash/read/MCP；换机器换工作流，省量会变。
3. `blank-runs` 仍是单向步骤：空行数量不可还原（内容语义不受影响）。

# v1.1.0 —— 可恢复性 / 保真 / 性能

> 2026-11-23。这一版不是"裁得更狠"，而是"同样预算下信息更全、说明更短、恢复更便宜"。

## 起因

对 202 个真实会话、20,930 条真实工具结果做了一轮独立测评，并跑了 22 个对抗用例与恢复路径/返工实测。
结论：v1.0.16 省量确实大（同批 13,755 条结果 token −40.4%），但有五处会**伤到判断**、一处**伤到可恢复性**：

| # | 问题 | 后果 |
| --- | --- | --- |
| 1 | 超长单行被切成"伪行"，有的片段不带标记 | 模型会把半行当完整行读 |
| 2 | 尾段可能退化成"原文中间的 2 个字符" | 结论 / 退出码 / footer 可能整个消失 |
| 3 | 非 `read` 的 `lines a-b` 与 `M lines` 对不上 | 说明行自相矛盾，模型无法判断缺多少 |
| 4 | 多文本块可突破预算（20 块 → 4.7 倍） | "内联预算"不再是上界 |
| 5 | 1200 预算下"点名被丢掉的报错"恒为空 | 编译报错只剩计数、没有根因 |
| 6 | 95.5% 的裁剪没有任何取回路径 | 想看中段只能重跑整条命令（read 返工率 51.7%） |

## 改法

- **长行是一个单元**：`lib/sections.js` 不再把长行切碎，`lib/clip.js` 在码点边界带 `⟨…+N⟩` / `⟨+N…⟩` 标记地截头/截尾；
  最后一行超长时用 `clipBoth` 同时保留行首（结论）与行尾（真正的结束）。
- **行号是事实来源**：单元自带 `line` / `lines`，行数、区间、省略字符三者从同一个行集合推导，
  并删掉了 O(n²) 的 `indexOf` 位置反查（这就是 24% 提速的来源）。
- **预算有硬上界**：多块按比例分配 + 每块保底 160 字符；块太多时整块换成一行可恢复说明。
- **说明行独立结算**：说明占预算的一个固定份额（≤240 字符），按真实长度收敛；`chars + 成品长度 == 原文长度` 用不动点钉死。
- **可恢复性**：`lib/spill.js` 把被拿掉的中段写到 `~/.dsh/tto/<content-hash>.txt`，说明行给出 `middle: <path>`；
  内容寻址（同一中段永远同一路径）、TTL 168h、上限 200MB、失败自动退回「重跑」提示。
- **幂等**：已经是本插件成品的结果不再二次裁剪（会话恢复/重放不会叠两层说明）。

## 对照（同批 13,755 条真实结果，`inlineChars: 1200`）

| 指标 | v1.0.16 | v1.1.0 |
| --- | ---: | ---: |
| 压缩后 token（估算） | 1,483,605 | 1,465,772 |
| 省量（原始 2,487,968） | 40.4% | 41.1% |
| 丢报错行且说明没提 | 39 | 14 |
| 算术不自洽 | 2 | 0 |
| 超预算文本块 | 0 | 0 |
| 说明行平均 / 最长 | 123.2 / 327 | 120.7 / 240 |

| 测试 | 102 | 111（含 16,549 条真实语料） |

复现：

```bash
# 取 v1 基线

# 跑对照
```

## 配置新增

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `recovery` | `hint` | `spill` = 中段落盘并给出路径；`hint` = 只给「重跑」提示 |
| `recoveryDir` | `~/.dsh/tto` | 落盘目录 |
| `recoveryTtlHours` | `168` | 保留时长 |
| `recoveryMaxMB` | `200` | 目录上限（超限按最旧清理） |

## 仍未解决

1. 报错行若落在**被截断的超长单行内部**，说明行仍不会点名（按行计数的机制看不到行内片段）。
2. 预算按**字符**计：中文实际约 1 字符/token，纯中文结果被"少裁"约 4 倍；要改得换 token 口径，属于行为变更。
3. ANSI 转义与 NUL 仍按字符计价、不清理。
